# Тексты песен: памятка Тане и инструкция ChatGPT

**Первый раз? [Таня, начни здесь](tanya-start.md)** — как принять приглашения,
попросить агента клонировать оба репозитория и запустить репозиторный скилл
[`tanya-texts`](../.agents/skills/tanya-texts/SKILL.md).

## Что говорить приложению

Открой **папку всего репозитория** `cherry-daddies-alex` в ChatGPT Desktop/Codex
в режиме работы с файлами и терминалом. Первый запрос:

> Прочитай AGENTS.md. Помоги мне работать с текстами песен. Я не умею пользоваться
> Git: выполняй команды сама, показывай превью и подтверждай сохранение на GitHub.

Дальше достаточно обычных фраз:

> Подготовь экранный текст для «Название». Песня скачана в JamZone.

> Подготовь текст для «Название» из вокального файла в Downloads. Сначала
> распознай слова сама, затем покажи видео для проверки.

> На 1:24 должно быть «…». Эти две строки объедини. Покажи новое превью.

> Я посмотрела превью, всё верно. Сохрани.

> Я посмотрела превью, всё верно. Сохрани и отправь клавишнику.

**«Сохрани»** — история изменений и файлы отправлены в основной GitHub-репозиторий.
**«Отправь клавишнику»** — готовый сценический клип отправлен также в GitHub рига.
Клавишник получает его на ноутбук через Pull перед работой с MainStage.
Если приложение говорит «push не удался», в GitHub ещё не сохранено: попроси
исправить причину и повторить отправку.

## Первичная настройка (вместе с Alex или агентом)

1. Войти на GitHub как `tkozinets`, принять приглашение в
   [cherry-daddies-alex](https://github.com/alexomee/cherry-daddies-alex/invitations).
2. Принять уже отправленное `basbit` приглашение в приватный
   [cherry-daddies-2000](https://github.com/basbit/cherry-daddies-2000/invitations).
   Затем агент проверяет реальные write-права вошедшего аккаунта `tkozinets`.
3. Установить ChatGPT Desktop с режимом Codex/работы с локальной папкой.
   Простое подключение GitHub к обычному чату не заменяет локальную работу.
4. Если на Mac нет Git, агент помогает установить Apple Command Line Tools через
   `xcode-select --install`; пользователь подтверждает системное окно. Дождаться
   завершения и проверить `git --version`. Полный Xcode не требуется.
   Затем установить Homebrew по [brew.sh](https://brew.sh) и `brew install gh`.
   Авторизоваться: `gh auth login --hostname github.com --git-protocol https --web`,
   затем `gh auth setup-git`. Браузерный вход делает сама Таня.
5. Клонировать **оба** репозитория в соседние папки:

   ```bash
   mkdir -p ~/Music/CherryDaddies
   cd ~/Music/CherryDaddies
   gh repo clone alexomee/cherry-daddies-alex
   gh repo clone basbit/cherry-daddies-2000
   ```

   Риг содержит аудио и историю — его первая загрузка может быть большой.
6. Настроить имя и GitHub email локально **в каждом репозитории** (агент спрашивает
   адрес, можно взять GitHub noreply из Settings → Emails). Пример:

   ```bash
   git -C ~/Music/CherryDaddies/cherry-daddies-alex config user.name 'Tatiana Kozinets'
   git -C ~/Music/CherryDaddies/cherry-daddies-alex config user.email '<GitHub email>'
   git -C ~/Music/CherryDaddies/cherry-daddies-2000 config user.name 'Tatiana Kozinets'
   git -C ~/Music/CherryDaddies/cherry-daddies-2000 config user.email '<GitHub email>'
   ```

7. Запустить двойным кликом `tools/lyric-launcher/setup.command` в основном репо.
   Он установит нужные утилиты и Python-окружение. Локальная модель транскрипции
   скачивается при первом использовании; после загрузки работает без API-ключа.
8. Открыть JamZone, скачать нужные песни. Затем попросить агента выполнить `doctor`.

Путь рига по умолчанию — соседний `cherry-daddies-2000`. Другой путь передавать
через `--rig /путь/к/репо` перед подкомандой или `CHERRY_RIG_REPO`.

### Какие данные Git не скачивает

Полный основной репозиторий включает инструменты, конфигурации, тексты, вики,
контент и их историю. Его `.gitignore` исключает большинство тяжёлых медиа.
Для конкретной песни нужны:

- JamZone: скачанная песня с `tiles.json`;
- русская/внешняя песня: вокальный стем или запись для транскрипции (передаёт Alex);
- музыкальный/вокальный **guide в таймлайне сценического плейбека** для превью
  (обычно `<song>/auto-render/all.wav`, передаёт Alex или восстанавливает агент);
- актуальные click/cues и плейбек из Git-репозитория рига;
- для исходного JamZone-времени — `auto-render/timeline.json` с `offset_sec`
  либо явно известное смещение.

Не приравнивать скачанный оригинал песни к нашей аранжировке. Иной темп, обрезка
интро, перестановки секций требуют выравнивания. Одного offset для них недостаточно.
Не использовать preview с уже подмешанными click/cues как чистый guide: они
добавляются из рига при review, иначе прозвучат дважды.

## Команды для агента

Все примеры выполняются из корня основного репо; `14` — **пример**, номер нужной
песни смотреть в `tools/lyric-launcher/songs.tsv`. Номера не переназначать при
перестановке сетлиста. Переменные ниже — только сокращение команд:

```bash
PY=tools/lyric-launcher/.venv/bin/python
FLOW=tools/lyric-launcher/lyric_workflow.py
"$PY" "$FLOW" doctor
"$PY" "$FLOW" sync
```

`sync` делает fetch/fast-forward обоих репозиториев. При дивергенции останавливается.
Проверяет read-доступ; фактический write-доступ подтверждается push.

### A. JamZone

```bash
"$PY" "$FLOW" build 14 --audio 'music/songs/Artist - Title/auto-render/all.wav'
```

Для строки `source=jamzone` берутся `cat` и локальный `tiles.json`, offset — из
`timeline.json`. Можно передать `--offset ЧИСЛО`. Папка JamZone переопределяется
через `JAMZONE_JAMS`. Если существует `lyrics-timed/NN.tsv`, он приоритетнее:
это редактируемая playback-time версия, уже содержащая offset.

### B. Транскрипция русской песни

Apple Silicon (в setup это backend по умолчанию):

```bash
"$PY" tools/lyric-launcher/transcribe_lyrics.py '/путь/к/vocals.wav' \
  --language ru --offset 3.187 --out tools/lyric-launcher/lyrics-timed/14.tsv
```

`3.187` — **пример**, не универсальное смещение. Для вокала, который уже экспортирован
в таймлайне финального плейбека, использовать `--offset 0`. Для исходного стема —
измеренный offset из его рендера. При вырезанном фрагменте учитывать ещё начало
фрагмента. Backend `mlx` использует `mlx-community/whisper-large-v3-turbo`;
`--model mlx-community/whisper-large-v3-mlx` выбирает полную модель.

На Intel Mac используется `--backend faster` с `faster-whisper`, модель `large-v3`.
Можно запускать без setup через `uv run --python 3.12 --with mlx-whisper` (либо
`--with faster-whisper`) перед `transcribe_lyrics.py`. Для повторного запуска без
сети у uv есть `--offline`; веса модели также должны быть скачаны ранее.

Результаты рядом:

- `14.tsv` — редактируемые строки с playback-таймкодами;
- `14.raw.json` — полное распознавание, вероятности, хеш аудио и смещение;
- `14.review.txt` — участки для особого внимания.

Повторы сохраняются. Длинные фразы разбиваются по измеренным word timestamps.
Существующие файлы не перезаписываются без явного `--replace`: сначала сохранить
ручные правки. Если есть готовый Whisper-совместимый JSON, использовать
`--from-json /путь/к/result.json`; придуманные таймкоды недопустимы.

Если текст уже проверен, а тайминги неудобны: существующие `align_lyrics.py`
(готовый Whisper JSON + текст) и `auto_align.py` (forced alignment по вокалу)
дают дополнительные способы выравнивания. Для последнего нужны `stable-ts` и
загрузка модели: `uv run --python 3.12 --with stable-ts python ...`. Не запускать
бесконечные повторные распознавания всей песни ради одной строки — выделить
сомнительный участок и сверить его с аудио.

### C. Сборка, ревью, исправления

```bash
"$PY" "$FLOW" build 14 --audio 'music/songs/Artist - Title/auto-render/all.wav'
"$PY" "$FLOW" review 14
```

Видео: `tools/lyric-launcher/.local/14-review.mp4`. Открыть его локальным
видеоплеером, например `open 'tools/lyric-launcher/.local/14-review.mp4'` на Mac.
Вокалистка видит сценические строки и время; слышит guide и актуальные click/cues
рига (click +10 dB, cues +5 dB относительно guide, общая peak-нормализация).

Проверить песню целиком: слова, все куплеты/повторы, вступления, паузы, конец и
читаемость. Правки — в `lyrics-timed/NN.tsv`, `lyrics-manual/NN.txt` либо
`overrides/NN.tsv` для JamZone (`replace/insert/delete<TAB>время<TAB>текст`).
Затем снова `build` и `review`.

Программа проверяет диапазоны времени, соответствие длительности reference и
рига (допуск 0.25s), хеши исходников, клипа и аудио. Это не заменяет человеческую
проверку синхрона и слов. Для намеренно отличающейся длины сначала подготовить
правильный playback-frame guide, а не отключать проверки.

Только после явного подтверждения вокалистки:

```bash
"$PY" "$FLOW" approve 14 --reviewer Татьяна
"$PY" "$FLOW" check 14
```

`reviews/NN.json` хранит воспроизводимые хеши и подтверждение; локальные пути и
видео — в `.local/`, вне Git. После клонирования на другой компьютер build/review
выполняются заново: старое подтверждение не распространяется на новую сборку.

### D. «Сохрани»

```bash
"$PY" "$FLOW" save 14 --message 'lyrics: исправить второй припев'
```

В commit входят источники выбранной песни, ASS, её review receipt и манифест.
Чужой staging и изменения других строк манифеста блокируют случайный общий commit.
Изменения mix/timeline/генераторов требуют отдельного осмысленного commit.
MP4 остаётся локальным в основном репо и версионируется в риге при доставке.
Успех — только после push и подтверждения достижимости commit в удалённой ветке.

### E. «Отправь клавишнику»

После `save`:

```bash
"$PY" "$FLOW" deliver 14              # показать план
"$PY" "$FLOW" deliver 14 --apply      # применить, commit, push
```

Совместимый вход: `bash tools/lyric-launcher/deploy_clips.sh --index 14 --apply`.
Прежнее массовое копирование всех локальных клипов заменено выбранной песней.

В риг едут `lyrics/clips/NN.ass`, `NN.mp4`, выбранная строка `lyrics/songs.tsv`
и `lyrics/deliveries/NN.json` со ссылкой на исходный commit. Чужие песни сохраняются.
Если коллега изменил эту песню/аудио после ревью, доставка останавливается до
пересборки и повторного ревью. При неудачном push commit остаётся: повторная
команда отправит его без создания дубликата.

Агент выдаёт ссылки вида `https://github.com/OWNER/REPO/commit/SHA` и сообщает:
**«В GitHub рига отправлено; клавишнику осталось сделать Pull».**

### F. Совершенно новая песня

Агент сверяет основной и rig-манифесты, выбирает свободный clip/PC и добавляет
одну строку в основной `songs.tsv`. `pc_field = clip + 1`, существующие clip-ID
стабильны. `bed_dir` должен указывать на подготовленный сценический плейбек в риге.
Если плейбек ещё не подготовлен, это отдельная музыкальная задача с Alex.

После доставки нового клипа клавишник проверяет External Instrument:
`LyricLauncher`, Send Program Change = `pc_field`, транспорт Start/Stop.
Запускать launcher перед MainStage. Подключение определяется по актуальному
`.concert`, а не по наличию строки манифеста; автоматическая доставка его не тестирует.

## Проверки для разработчика

```bash
uv run --python 3.12 --with pytest pytest tools/lyric-launcher/tests -q
```

Тесты используют временные Git-репозитории/bare remotes, настоящий ffmpeg/ffprobe
и отдельный короткий mpv-рендер. Проверяют выборочную доставку, stale review,
обновления коллег, отказы push и повторную отправку. Боевой риг не используется.
