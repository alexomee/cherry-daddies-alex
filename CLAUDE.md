## Cues (вокальные подсказки в ухо)

Когда пользователь даёт список cue (обычно позиции из Logic: `такт доля`), текст разворачивается по фиксированным правилам. **Очень важно, действует для ВСЕХ cue, всегда:**

- `{инструмент} in` → произносится **«{инструмент} in ready go»** (напр. `guitar in` → «guitar in ready go»).
- `{x} stop` → объявление **«{x} stop in 3»**, затем отсчёт **«3 2 1»** на три доли перед стопом (клипы `~/3,2,1.aiff`). Стоп — на доле после «1» (напр. `all stop` → «all stop in 3», 3-2-1, стоп).
- **Счётный вход/конец** (`"count": true` у cue в mix.json) → объявление **«{текст} 3»** + отсчёт **«3 2 1»** (как у стопа, но вход/конец, не стоп). Для случаев, где группа хочет счёт «3 2 1» вместо «ready go» (напр. `bass-only in` → «bass only in 3, 3 2 1»; `end in` → «end in 3, 3 2 1»). Событие (вступление/финальный хит) — на доле после «1».
- Заданный `такт доля` = **сама точка события** (где инструмент вступает / где стоп) — на ней в cue-треке ничего не звучит, играешь/останавливаешься именно на ней. Для `in`: последнее слово (`go`) на долю ПЕРЕД событием, инструмент вступает на следующую долю. Для `stop`: «1» на долю перед стопом, «3 2 1» на три доли до него.
- Стартовый cue = название песни + что вступает + ready go (напр. «Мало тебя guitar in ready go»).
- Позиции даются как `такт доля` в темпе песни; доля по умолчанию = 1.
- Слово через дефис = ОДНО слово (напр. `soft-verse`, `bass-n-beat`, `lead-and-pad`). Ускорение речи — максимум `say -r 200` (быстрее — неразборчиво). Мелкий перелив (<0.15 доли, напр. `solo`/`sax`) мягко ужимается в долю (на слух незаметно); слово, которое НЕ влезает с большим переливом (напр. `instrumental`), НАЧИНАЕТСЯ на долю раньше и занимает 2 доли натуральным темпом (перед ним в счётном блоке пусто, событие и остальные слова не двигаются).
- Название песни в стартовом cue не ужимается: звучит в естественном темпе в пустом такте перед счётным блоком, выровнено по концу (заканчивается перед первым словом блока).
- Если длинный cue (название песни) **реально не влезает** перед своим событием (обрезается спереди) — рендер добавляет целые такты спереди (count-in), чтобы фраза не обрезалась. Если cue и так влезает — лишний пустой такт НЕ добавляется (порог clearance 0.05с). В добавленных тактах ВСЕГДА звучит клик (JZ-сэмплы, акцент на 1). Номера тактов в mix.json при этом не меняются.
- **Быстрые песни — `"cue_step": N` (на уровне песни в mix.json, дефолт 1).** N = сколько ДОЛЕЙ занимает каждое размеренное слово блока (и каждый сегмент отсчёта «3 2 1»). На быстром темпе (напр. Blinding Lights 171 bpm, доля = 351мс) слово-на-долю не разобрать в ухе → `"cue_step": 2` растягивает: каждое слово на 2 доли (≈700мс), `go` за 2 доли до события, блок «{x} in ready go» занимает 8 долей (2 такта) вместо 4. Cобытие/тайминг музыки НЕ двигаются. Можно переопределить на отдельном cue полем `"step": N`. (Обратное к `subdiv` у tempo-зоны: тот ПАКует слова в под-доли, `cue_step` РАЗДВИГАет.) ВАЖНО: при N>1 блок длиннее → стартовый cue (название+блок) часто перестаёт влезать спереди → рендер добавляет count-in такт, и все render-таймкоды съезжают на +1 такт (музыка относительно клика не двигается).

## Оцифровка старых cue (`<Song> cues.mp3` → `mix.json`)

Для песен с прошлой версией cue (bounce cue-трека из Logic, обычно `~/Downloads/<Song> cues.mp3`) список `{bar, beat, text}` восстанавливается из mp3. Проверено на Infinity 2008 и Now You're Gone:

1. **Транскрипция** (mlx-whisper через uvx, модель кэшируется после первого раза):
   ```bash
   uvx --python 3.12 --from mlx-whisper mlx_whisper "<cues.mp3>" \
     --model mlx-community/whisper-small-mlx --word-timestamps True \
     --output-format json --output-dir /tmp/<song>_cues --language en
   ```
   Word-таймстемпы повторяющихся цифр («3 2 1») на полном файле — мусор (спаны через минуты тишины). Мутные фразы резать ffmpeg'ом в клипы по 2–5с и транскрибировать отдельно — на коротких клипах галлюцинаций нет.
2. **Границы фраз** — по энергетической огибающей mp3 (RMS, порог ~5% пика, склейка пауз <0.45с), не по whisper-таймстемпам.
3. **Сетка** — `fit_grid` из `01_Click.m4a` (`tools/jamzone/jamzone_render.py`): bpm, downbeat.
4. **Смещение таймлайна mp3 ↔ сетка — НЕ предполагать, а измерять** по жёсткому стем-якорю: точный онсет барабанов/баса, который обязан лежать на барлайне. Прецеденты: Infinity — t=0 mp3 = первый клик (такт 1, смещение 0); NYG — бонс начался на 1 долю раньше такта 1. Кажущаяся «другая конвенция отсчёта» = на самом деле смещение.
5. **Математика отсчёта**: последняя «1» (или «go») лежит на доле ПЕРЕД событием → событие = следующая доля. Конвенция одна для всех песен.
6. **Каждое событие сверить со стемами**: регионы активности (RMS по тактам, порог ~2% пика стема) + точные онсеты у кандидатов. Затакты (сакс, вокал) дают ранний RMS-регион (свелл/дыхание) — позицию брать из отсчёта, регион только для подтверждения.
7. Черновик таблицы (такт.доля / старый текст / якорь в стемах / новый текст) — **показать пользователю до рендера**: старые тексты часто голые «3 2 1», формулировки правит он. Потом `mix.json` → `jamzone_render.py "<song>"` → слушать `auto-render/cue_preview.mp3`.

## Внешние песни (Moises-стемы)

Пайплайн: zip из Moises → `music/songs/<Artist - Title>/`, стемы переименовать в `bass|drums|guitars|keys|other|vocals|metronome.mp3` → `mix.json` (`bpm` = число из имени Moises-файла, оно почти всегда верно; `pitch_semitones` под тональность группы; `cues`) → `tools/jamzone/jamzone_render.py`. Два молчаливых гоча Moises — проверять ДО рендера:

1. **Локальный дрейф.** Moises-метроном следует записи: брейкдаун без барабанов / аутро могут уплыть на десятки мс при идеальном среднем темпе (Солнышко: +52мс в брейкдауне при глобальных ±10). Чек: `tools/jamzone/jamzone_warp_ext.py "<song>" --bpm N --check` (кривая отклонения). Если не ±10мс — варп тем же скриптом без `--check`: все стемы тянутся одной сглаженной кривой (синхронизация между стемами не трогается), оригиналы → `moises-orig/`.
2. **Первый клик ≠ сильная доля.** Рендер берёт downbeat = первый клик метронома, но Moises может начать счёт с середины такта (Солнышко: такт начинался с клика 2; акцентов в клике Moises нет — ни по частоте, ни по громкости). Чек: смены гармонии по битам (хрома-флакс mod 4 на keys+other+guitars+bass) — пик должен быть на k%4==0 от первого клика; иначе `--downbeat K` у варпа (глушит клики до настоящей сильной доли). Границы секций (вступление баса, брейкдаун) обязаны лечь на тактовые линии — это контрольная сверка.

**Реальная смена темпа в середине** (не дрейф, а замысел — напр. half-time брейкдаун): НЕ лечить варпом и не игнорировать константной сеткой (после зоны накопится дрейф в целые доли, и сильная доля музыки уедет на чужую долю клик-такта — Я устал: +11 долей после зоны). Вместо этого `"click": "follow"` в mix.json: рендер строит клик и cue-сетку с переменным темпом — стабильный 124 в ровных секциях (чистый fit, клавишнику есть подо что играть), медленный темп в зоне, а ПОСЛЕ зоны фаза перезахватывается lstsq-фитом реальных онсетов метронома, так что клик снова ложится на музыку (арп/клавиши тайтовые, проверено 100% на киках). `bpm` оставить (главный темп — длины тактов/lead). cue в зоне отсчитываются по локальному темпу.

**СУБДИВИЗИЯ клика в зоне** (`"subdiv": N` в tempo_zone, N=2 → 8-е, 4 → 16-е; default 1 = только доли). КРИТИЧНО для синкопированных брейкдаунов: half-time грув часто ведётся 16-ми (бэкбон-удары на «и» доли — позиция «3+» бывает чаще самого даунбита). Клик только на четвертях тикает на каждый ВТОРОЙ/ЧЕТВЁРТЫЙ удар и пропускает синкопу — пользователь ставит плейхед на громкий удар, а клика там нет (Я устал: четверти 21% киков с кликом, 8-е 53%, 16-е 95%). Перед выбором разрешения ОБЯЗАТЕЛЬНО строить гистограмму энергии кик+снейр+бас по 16-позициям такта зоны и смотреть, на каких под-долях структурные удары. Иерархия акцентов: даунбит бара (loud), доли (medium), под-доли (quiet). Проверка фикса — методом ПОЛЬЗОВАТЕЛЯ: для каждого громкого транзиента музыки ближайший клик, %>60мс по секциям (не «средняя ошибка по ближайшему» — она прячет пропуски). НЕ путать половинный/двойной темп: медиана интервала громких ударов — ловушка half-tempo (бэкбит каждые 666мс есть, но между ними равноценный удар через 333мс → реальный пульс вдвое чаще).

Зона по умолчанию авто-детектится из отклонений интервалов метронома. НО Moises-метроном может ВРАТЬ на переходе (Я устал: драм-брейк, реальные слоу-кики с 105.0с, а метроном держит 124 до 107.1с и пересчитывает брейк) — тогда зону задать ВРУЧНУЮ: `"tempo_zone": {"from_bar": N, "to_bar": M, "bpm": Z, "anchor_sec": T}` (опц. `from_beat`/`to_beat`). `from..to` — диапазон долей слоу-секции, `bpm` — медленный темп, `anchor_sec` (стем-секунды) фазирует первую долю зоны на реальный слоу-даунбит. ВАЖНО: якорить на РОВНУЮ часть брейкдауна, не на пикап-вход — края (1 бар входа после драм-брейка, 1 бар выхода) в записи неровные/сжатые, их не вытянуть; ровная середина бьёт ±6мс. Брейкдаун-даунбиты искать по громким кикам (lowpass <120Гц): взять серию ~ровных ~2.6с гэпов, anchor на первый ИЗ РОВНЫХ (не на короткий стартовый бар). Бар может гулять — проверять весь диапазон, выбирать bpm по медиане ровных баров. Привязка проверяется: клик на слоу-даунбитах кика ±5мс. ВАЖНО: исходный cue-клик из старого Logic-проекта (`*сорс клик*`) НЕ годится как референс — он с другого таймлайна, на Moises-стемы не ложится (Я устал: 24% на киках против 90% у Moises-метронома).

## Practice-микс (играющий учит свою партию)

Per-song `mix.json` ключ `players` — кто что играет ЖИВЬЁМ в этой песне: `{"alex": ["guitars"]}` (имена стемов/лейеров). На КАЖДЫЙ полный рендер (без флага) для каждого игрока пишется `auto-render/practice-<player>.mp3` = весь микс БЕЗ его стемов + клик + cue, на уровнях cue_preview (all·0.85 + click·0.6 + cues·1.0). Партия игрока — В НОЛЬ (не тихий гайд): играешь её сам поверх. Минус питчится в ключ группы (`pitch_semitones`, как `all`); лейеры уже в ключе группы — те, что игрок НЕ играет, добавляются в минус (напр. чужой живой бас остаётся). Стем игрока валидируется как pb-other (нет такого стема/лейера → exit). Нет ключа `players` → ничего не пишется (обратно совместимо). Какой стем «мой» — per-song (Moises: гитара=`guitars`, синт обычно `other`/`keys`), заполняется отдельным проходом по песням.

## Вклады участников в pb-other/pb-bass (`layers`)

Когда участник (клавишник, гитарист, басист) присылает СВОЮ записанную партию (синт/шум/DI/бас) для плейбека — это **`layer`**, а НЕ стем. Партия **ВСЕГДА уже в тональности группы** (её играют под живую банду) → **layer НИКОГДА не питчится**. Меняется только ВРЕМЕННОЙ ФРЕЙМ — подо что человек играл при записи:

- **frame `render`** (дефолт; запись слушает мой `auto-render`/`all.wav`): файл уже несёт каунт-ин/lead и темп рендера → кладётся **1:1 с индекса 0** (без `off_samp`).
- **frame `stem`** (запись слушает сырые Moises-стемы): нативный таймлайн без lead → кладётся **на `off_samp` (OFF)**, ровно где сидят стемы.

Скармливать как обычный moises-стем НЕЛЬЗЯ: стем питчится по `pitch_semitones` (а partия уже в ключе → двойной питч) и (для render-фрейма) сдвигается на лишний OFF.

`jamzone_render.py`, группы `pb-other`/`pb-bass`, поле `"layers": [...]` рядом со `"stems"`:
- **источник = и есть layer**, обработки ноль. Оригинал → `<song>/parts/<name>.{wav,mp3,aif}` (read-only). `parts/` ВНЕ нерекурсивного glob стемов → не станет авто-стемом, не утечёт/не спитчится в `all`.
- запись: `"name"` (=render-фрейм) **или** `{"file":"name","frame":"render|stem","offset_ms":N,"gain_db":N,"replaces":["bass"]}`. Кладётся ПОСЛЕ питч-пасса (значит без питча), ДО хедрум-нормализации; подмешивается в свою группу И в `all`. Стемы опциональны (дуо: часто только layer).
- **`replaces`**: если layer ПЕРЕ-записывает moises-стем (живой бас вместо студийного) — указать `"replaces":["bass"]`, иначе в `all`/превью ДВА баса (студийный + живой). Рендер выкидывает эти стемы из `all`. Печатает `all: ... excluded: [...]`.
- **ФРЕЙМ И КЛЮЧ — НЕ ПРЕДПОЛАГАТЬ, А МЕРИТЬ.** Фрейм: широкая (±OFF+запас) кросс-кор огибающей layer vs `drums.mp3` → пик ~0мс = `stem`, пик ~+OFF = `render`. Ключ: хрома-профиль layer vs `bass.mp3`/`keys.mp3`, лучший круговой сдвиг = транспозиция (0 = ориг.ключ; совпал с `pitch_semitones`, напр. −2 = уже в ключе группы). Медиана f0 НЕ годится (разные ноты у живой/студийной партии — путает).
- остаточный сдвиг (латентность/фил живой записи) — `offset_ms` (+ задержать). Слабый corr у баса-vs-баса (живая ≠ студийная партия) ненадёжен для фазы — фрейм мерить по драмам, фазу доверять уху.
- **валидность только против того, подо что писали**: переписал cue (изменился OFF) → render-фрейм layer невалиден (stem-фрейм — нет), просить перезаписать. Layers — ПОСЛЕ заморозки cue.
- Прецеденты: Band'Eros «Pro krasivuju zhizn'» — `parts/keys-noise.wav`, **render**-фрейм, lag +0мс. SEREBRO «Malo tebya» (`pitch_semitones:-2`) — `parts/malo-bass.aif`, **stem**-фрейм (записан под Moises-стемы), хрома −2 = уже в ключе → без питча, на OFF.

## Загрузки с YouTube

- **Скрипт:** `tools/yt-download.sh <url> [audio|video|both]` — обёртка над `yt-dlp` (homebrew).
- **Режим по умолчанию:** `audio` — лучшая аудиодорожка, перекодируется в **mp3 (V0 VBR)** через `yt-dlp -x --audio-format mp3 --audio-quality 0`.
- **ПРАВИЛО: только mp3, не webm/opus.** Никаких нативных контейнеров в `music/youtube/` — mp3 открывается в Logic/GarageBand и везде. Если webm всё же появился — конвертировать в mp3 (`ffmpeg -i x.webm -c:a libmp3lame -q:a 0 x.mp3`) и удалить webm.
- **Куда падает:** `music/youtube/` — единая папка для всех YouTube-загрузок. В `music/songs/` ничего не класть.
- **Имя файла:** `<title> [<video id>].mp3` — id в имени, чтобы источник был восстановим и версии не перезаписывались.
- **Git:** тяжёлые медиа вне git (`*.mp3`, `*.webm`, `*.opus`, `*.mkv` в `.gitignore`, как и остальное аудио/видео).

## Тексты на сцене (lyric-launcher)

Синхронные тексты на сценический монитор, гонится из MainStage клавишника. **Размазано по ДВУМ репам:** `tools/lyric-launcher/` ЗДЕСЬ = **фабрика** (генерация); деплой → `~/projects/cherry-daddies-2000/lyrics/` = **риг** (рантайм на ноуте клавишника) + `2000.concert`. Деплой клипов = как биды (`deploy_clips.sh`). Полная картина: `cherry-daddies-2000/lyrics/README.md` + `docs/plans/2026-06-18-lyric-launcher-handover*`.

- **Два типа клипов** (оба = `clips/NN.mp4`+`NN.ass`, launcher играет одинаково): timed-караоке из JamZone `tiles.json` (`make_song_clip.py`, текущая+следующая строка); **static «весь текст на экране»** для не-JamZone (`make_static_clip.py`, колонки, повторы → `×N`). `NN` = номер сета = номер клипа.
- **Триггер MainStage — НЕ менять флоу клавишника:** PC на set-change **armит** клип (название, пауза); пэд **E1** (Play/Stop action глоб.транспорта) шлёт MIDI **Start/Stop** → roll/freeze. MainStage **позицию плейхеда не отдаёт** (нет SPP, Playback Play молчит) → scrub/авто-скролл невозможны, проверено — не пытаться.
- **Порт:** виртуальный `LyricLauncher` (one-way, без петли), launcher сам ставит **стабильный CoreMIDI uniqueID 0x4C595243** (иначе MainStage теряет привязку на каждом рестарте). НЕ IAC (loopback → петля PC / играющее пианино). **Launcher запускать ДО MainStage** (порт существует только пока launcher жив).
- **`.concert` = бинарные plist** (plutil/plistlib). Wiring = добавить `Lyrics.cst` External Instrument в `data.plist` `channels` (`MIDIOutputPort=LyricLauncher`+uniqueID, `programChangeNumber = clip`; UI-поле «Send Program Change» = clip+1, 1-based). Делает `wire_concert.py` идемпотентно — **только на копии, MainStage закрыт.** MainStage пере-сериализует ~470 файлов на каждый save → шумные коммиты, это норма. Дивергенция бинарников: **не мержить** — сбросить wiring-коммит → rebase lyrics-коммитов (они не пересекаются) → пере-запустить `wire_concert.py` поверх.
- **РЕГРЕССИЯ-ГАРД: `wire_concert.py` НЕ затирает ручной фикс клавишника.** Дефолтно Lyrics-страйп — полнодиапазонный слой на ПЕРВОЙ клаве (Akai), он перехватывает игру и шлёт ноты в LyricLauncher. Клавишник правит это руками per-set: `Channel_outputIndex=-1` (No Output, в `data.plist`) + диапазон/зона слоя живёт в **OCuA-блобе `Lyrics.cst`** (где именно — НЕ в `data.plist`: проверено по 2149 патчам, нет ни одного key-range поля; после save MainStage делает каждый `Lyrics.cst` уникальным). Поэтому wire: (1) **никогда не перекопирует существующий `Lyrics.cst`** (только сидит новый сет; `--force-cst` чтобы силой) — иначе ревертит фикс; (2) трогает в `data.plist` ТОЛЬКО PC-проводку (output-port/PC/programChangeNumber), не output-routing/диапазон; (3) новый страйп рождается No-Output (`Channel_outputIndex=-1`), `.cst` для нового сета сидится из уже-фикснутого сета-донора. Проверка: повторный прогон по фикснутому концерту = **полный no-op** (deep-diff пустой, все `.cst` побайтно те же). Тест: `tests/test_wire_preserves_fix.py`. pb-апдейты (`sync_to_mainstage.sh`) и клипы (`deploy_clips.sh`) `.concert` НЕ трогают — там реверта нет.
- **Маппинг сетов — из `web/songs.json`** (позиция в `sets[].songs[]` = номер сета), не из имён папок. `build_manifest.py` → `songs.tsv` (set·clip·pc·source·cat·factory_dir·bed_dir·concert_patch).
- **Лирика русских/не-JamZone песен:** WebFetch/summarizer ОТКАЗЫВАЕТ (copyright) — брать `fetch_lyrics.py` (curl + extract сырого HTML), чистить, класть в `lyrics-manual/NN.txt`.

## Обновление playback/cue в риге (MainStage) после ре-рендера

Перерендерил песню (`jamzone_render.py` → новые `click/cues/pb-other/pb-bass.wav` в `auto-render/`) → стемы в боевом MainStage-проекте (`cherry-daddies-2000`) **НЕ обновятся сами**. Накатывает `tools/sync_to_mainstage.sh`.

- **Что делает:** для каждой песни сетлиста копирует из `<song>/auto-render/` в `cherry-daddies-2000/cherry-daddies-setlist-2026-06-16/<NN Song>/` **только те стемы, что УЖЕ лежат в целевой папке** (`click/cues/pb-other/pb-bass.wav`), перезаписывая на месте. `all.wav`/`cue_preview.mp3`/`timeline.json` — пайплайн-внутренние, не копируются. MainStage ссылается на аудио ПО ПУТИ → перезапись 1:1 = плагин видит новый звук без правок.
- **Дефолт — dry-run** (показывает, что бы изменилось, с размерами). `--apply` пишет. Фильтр по подстроке: `tools/sync_to_mainstage.sh --apply "S&M"`. Коммит в риге (без push): `--apply --commit "S&M: re-render cues"`. Маппинг setlist-папка ↔ song-папка — табличка `MAP` в самом скрипте (не из `web/songs.json`).
- **`MISSING in render`** = в целевой папке стем есть, а в `auto-render/` нет → песню не дорендерили / стем переименован в `mix.json`. Чинить рендер, не скрипт.
- **НОВЫЙ или переименованный стем = РУЧНАЯ правка в MainStage, скрипт его НЕ заведёт** (и не удалит). Причина: путь к wav лежит ТОЛЬКО в бинарном `.cst`-блобе Playback-плагина (не в чистом `data.plist`), имя сет-папки переменной длины → бинарная хирургия хрупкая, рискует побить патч. Поэтому добавление стема (напр. впервые подмешать `pb-bass` к песне, где его не было) делается руками: открыть сет в MainStage → Playback-плагин → добавить дорожку на новый wav. В отличие от `wire_concert.py` (тот правит чистый plist-`channels` — там автоматизация безопасна), Playback-стемы авто-добавлять НЕ автоматизируем.
