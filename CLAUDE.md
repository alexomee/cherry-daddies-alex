## Cues (вокальные подсказки в ухо)

Когда пользователь даёт список cue (обычно позиции из Logic: `такт доля`), текст разворачивается по фиксированным правилам. **Очень важно, действует для ВСЕХ cue, всегда:**

- `{инструмент} in` → произносится **«{инструмент} in ready go»** (напр. `guitar in` → «guitar in ready go»).
- `{x} stop` → объявление **«{x} stop in 3»**, затем отсчёт **«3 2 1»** на три доли перед стопом (клипы `~/3,2,1.aiff`). Стоп — на доле после «1» (напр. `all stop` → «all stop in 3», 3-2-1, стоп).
- **Счётный вход/конец** (`"count": true` у cue в mix.json) → объявление **«{текст} 3»** + отсчёт **«3 2 1»** (как у стопа, но вход/конец, не стоп). Для случаев, где группа хочет счёт «3 2 1» вместо «ready go» (напр. `bass-only in` → «bass only in 3, 3 2 1»; `end in` → «end in 3, 3 2 1» вместо `end stop`). Событие (вступление/финальный хит) — на доле после «1».
- Заданный `такт доля` = **сама точка события** (где инструмент вступает / где стоп) — на ней в cue-треке ничего не звучит, играешь/останавливаешься именно на ней. Для `in`: последнее слово (`go`) на долю ПЕРЕД событием, инструмент вступает на следующую долю. Для `stop`: «1» на долю перед стопом, «3 2 1» на три доли до него.
- Стартовый cue = название песни + что вступает + ready go (напр. «Мало тебя guitar in ready go»).
- Позиции даются как `такт доля` в темпе песни; доля по умолчанию = 1.
- Слово через дефис = ОДНО слово (напр. `soft-verse`, `bass-n-beat`, `lead-and-pad`). Ускорение речи — максимум `say -r 200` (быстрее — неразборчиво). Мелкий перелив (<0.15 доли, напр. `solo`/`sax`) мягко ужимается в долю (на слух незаметно); слово, которое НЕ влезает с большим переливом (напр. `instrumental`), НАЧИНАЕТСЯ на долю раньше и занимает 2 доли натуральным темпом (перед ним в счётном блоке пусто, событие и остальные слова не двигаются).
- Название песни в стартовом cue не ужимается: звучит в естественном темпе в пустом такте перед счётным блоком, выровнено по концу (заканчивается перед первым словом блока).
- Если длинный cue (название песни) **реально не влезает** перед своим событием (обрезается спереди) — рендер добавляет целые такты спереди (count-in), чтобы фраза не обрезалась. Если cue и так влезает — лишний пустой такт НЕ добавляется (порог clearance 0.05с). В добавленных тактах ВСЕГДА звучит клик (JZ-сэмплы, акцент на 1). Номера тактов в mix.json при этом не меняются.

## Оцифровка старых cue (`<Song> cues.mp3` → `mix.json`)

Для песен с прошлой версией cue (bounce cue-трека из Logic, обычно `~/Downloads/<Song> cues.mp3`) список `{bar, beat, text}` восстанавливается из mp3. Проверено на Infinity 2008 и Now You're Gone:

1. **Транскрипция** (mlx-whisper через uvx, модель кэшируется после первого раза):
   ```bash
   uvx --python 3.12 --from mlx-whisper mlx_whisper "<cues.mp3>" \
     --model mlx-community/whisper-small-mlx --word-timestamps True \
     --output-format json --output-dir /tmp/<song>_cues --language en
   ```
   Word-таймстемпы повторяющихся цифр («3 2 1») на полном файле — мусор (спаны через минуты тишины). Мутные фразы резать ffmpeg'ом в клипы по 2–5с и транскрибировать отдельно — на коротких клипах галлюцинаций нет.
2. **Границы фраз** — по энергетической огибающей mp3 (RMS, порог ~5% пика, склейка пауз <0.45с), не по whisper-таймстемпам.
3. **Сетка** — `fit_grid` из `01_Click.m4a` (`tools/jamzone/jamzone_render.py`): bpm, downbeat.
4. **Смещение таймлайна mp3 ↔ сетка — НЕ предполагать, а измерять** по жёсткому стем-якорю: точный онсет барабанов/баса, который обязан лежать на барлайне. Прецеденты: Infinity — t=0 mp3 = первый клик (такт 1, смещение 0); NYG — бонс начался на 1 долю раньше такта 1. Кажущаяся «другая конвенция отсчёта» = на самом деле смещение.
5. **Математика отсчёта**: последняя «1» (или «go») лежит на доле ПЕРЕД событием → событие = следующая доля. Конвенция одна для всех песен.
6. **Каждое событие сверить со стемами**: регионы активности (RMS по тактам, порог ~2% пика стема) + точные онсеты у кандидатов. Затакты (сакс, вокал) дают ранний RMS-регион (свелл/дыхание) — позицию брать из отсчёта, регион только для подтверждения.
7. Черновик таблицы (такт.доля / старый текст / якорь в стемах / новый текст) — **показать пользователю до рендера**: старые тексты часто голые «3 2 1», формулировки правит он. Потом `mix.json` → `jamzone_render.py "<song>"` → слушать `auto-render/cue_preview.mp3`.

## Внешние песни (Moises-стемы)

Пайплайн: zip из Moises → `music/songs/<Artist - Title>/`, стемы переименовать в `bass|drums|guitars|keys|other|vocals|metronome.mp3` → `mix.json` (`bpm` = число из имени Moises-файла, оно почти всегда верно; `pitch_semitones` под тональность группы; `cues`) → `tools/jamzone/jamzone_render.py`. Два молчаливых гоча Moises — проверять ДО рендера:

1. **Локальный дрейф.** Moises-метроном следует записи: брейкдаун без барабанов / аутро могут уплыть на десятки мс при идеальном среднем темпе (Солнышко: +52мс в брейкдауне при глобальных ±10). Чек: `tools/jamzone/jamzone_warp_ext.py "<song>" --bpm N --check` (кривая отклонения). Если не ±10мс — варп тем же скриптом без `--check`: все стемы тянутся одной сглаженной кривой (синхронизация между стемами не трогается), оригиналы → `moises-orig/`.
2. **Первый клик ≠ сильная доля.** Рендер берёт downbeat = первый клик метронома, но Moises может начать счёт с середины такта (Солнышко: такт начинался с клика 2; акцентов в клике Moises нет — ни по частоте, ни по громкости). Чек: смены гармонии по битам (хрома-флакс mod 4 на keys+other+guitars+bass) — пик должен быть на k%4==0 от первого клика; иначе `--downbeat K` у варпа (глушит клики до настоящей сильной доли). Границы секций (вступление баса, брейкдаун) обязаны лечь на тактовые линии — это контрольная сверка.

**Реальная смена темпа в середине** (не дрейф, а замысел — напр. half-time брейкдаун): НЕ лечить варпом и не игнорировать константной сеткой (после зоны накопится дрейф в целые доли, и сильная доля музыки уедет на чужую долю клик-такта — Я устал: +11 долей после зоны). Вместо этого `"click": "follow"` в mix.json: рендер строит клик и cue-сетку с переменным темпом — стабильный 124 в ровных секциях (чистый fit, клавишнику есть подо что играть), медленный темп в зоне, а ПОСЛЕ зоны фаза перезахватывается lstsq-фитом реальных онсетов метронома, так что клик снова ложится на музыку (арп/клавиши тайтовые, проверено 100% на киках). `bpm` оставить (главный темп — длины тактов/lead). cue в зоне отсчитываются по локальному темпу.

**СУБДИВИЗИЯ клика в зоне** (`"subdiv": N` в tempo_zone, N=2 → 8-е, 4 → 16-е; default 1 = только доли). КРИТИЧНО для синкопированных брейкдаунов: half-time грув часто ведётся 16-ми (бэкбон-удары на «и» доли — позиция «3+» бывает чаще самого даунбита). Клик только на четвертях тикает на каждый ВТОРОЙ/ЧЕТВЁРТЫЙ удар и пропускает синкопу — пользователь ставит плейхед на громкий удар, а клика там нет (Я устал: четверти 21% киков с кликом, 8-е 53%, 16-е 95%). Перед выбором разрешения ОБЯЗАТЕЛЬНО строить гистограмму энергии кик+снейр+бас по 16-позициям такта зоны и смотреть, на каких под-долях структурные удары. Иерархия акцентов: даунбит бара (loud), доли (medium), под-доли (quiet). Проверка фикса — методом ПОЛЬЗОВАТЕЛЯ: для каждого громкого транзиента музыки ближайший клик, %>60мс по секциям (не «средняя ошибка по ближайшему» — она прячет пропуски). НЕ путать половинный/двойной темп: медиана интервала громких ударов — ловушка half-tempo (бэкбит каждые 666мс есть, но между ними равноценный удар через 333мс → реальный пульс вдвое чаще).

Зона по умолчанию авто-детектится из отклонений интервалов метронома. НО Moises-метроном может ВРАТЬ на переходе (Я устал: драм-брейк, реальные слоу-кики с 105.0с, а метроном держит 124 до 107.1с и пересчитывает брейк) — тогда зону задать ВРУЧНУЮ: `"tempo_zone": {"from_bar": N, "to_bar": M, "bpm": Z, "anchor_sec": T}` (опц. `from_beat`/`to_beat`). `from..to` — диапазон долей слоу-секции, `bpm` — медленный темп, `anchor_sec` (стем-секунды) фазирует первую долю зоны на реальный слоу-даунбит. ВАЖНО: якорить на РОВНУЮ часть брейкдауна, не на пикап-вход — края (1 бар входа после драм-брейка, 1 бар выхода) в записи неровные/сжатые, их не вытянуть; ровная середина бьёт ±6мс. Брейкдаун-даунбиты искать по громким кикам (lowpass <120Гц): взять серию ~ровных ~2.6с гэпов, anchor на первый ИЗ РОВНЫХ (не на короткий стартовый бар). Бар может гулять — проверять весь диапазон, выбирать bpm по медиане ровных баров. Привязка проверяется: клик на слоу-даунбитах кика ±5мс. ВАЖНО: исходный cue-клик из старого Logic-проекта (`*сорс клик*`) НЕ годится как референс — он с другого таймлайна, на Moises-стемы не ложится (Я устал: 24% на киках против 90% у Moises-метронома).

## Загрузки с YouTube

- **Скрипт:** `tools/yt-download.sh <url> [audio|video|both]` — обёртка над `yt-dlp` (homebrew).
- **Режим по умолчанию:** `audio` — лучшая аудиодорожка, перекодируется в **mp3 (V0 VBR)** через `yt-dlp -x --audio-format mp3 --audio-quality 0`.
- **ПРАВИЛО: только mp3, не webm/opus.** Никаких нативных контейнеров в `music/youtube/` — mp3 открывается в Logic/GarageBand и везде. Если webm всё же появился — конвертировать в mp3 (`ffmpeg -i x.webm -c:a libmp3lame -q:a 0 x.mp3`) и удалить webm.
- **Куда падает:** `music/youtube/` — единая папка для всех YouTube-загрузок. В `music/songs/` ничего не класть.
- **Имя файла:** `<title> [<video id>].mp3` — id в имени, чтобы источник был восстановим и версии не перезаписывались.
- **Git:** тяжёлые медиа вне git (`*.mp3`, `*.webm`, `*.opus`, `*.mkv` в `.gitignore`, как и остальное аудио/видео).

   ```bash
   zip -j "/tmp/<Song> auto-render.zip" *.wav cue_preview.mp3 -x "*.json"
   ```
2. **Креды R2** (НЕ хранить здесь — CLAUDE.md в git). **4 значения** лежат БАРЕ-строками `KEY=value` в `~/projects/agentiqa/docs/plans/2026-03-09-preview-release.md` (строки ~33–36): `R2_ENDPOINT` (`https://…74709cb38b6ab441aed5fb0ccd3409f3.r2.cloudflarestorage.com`), `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME` (=`agentiqa-releases`). ## Gemini API (контент-пиллар: смешные рилсы из реп)

Ключ Gemini (Google AI Studio, префикс `AIzaSy…`) живёт в репо `agentiqa` (НЕ хранить здесь — CLAUDE.md в git): var `AGENTIQA_GEMINI_API_KEY` в `~/projects/agentiqa/apps/desktop-next/.env` (также `.env.staging`, `.env.prod`). Достать:
```bash
grep '^AGENTIQA_GEMINI_API_KEY=' ~/projects/agentiqa/apps/desktop-next/.env | cut -d= -f2-
```

- **Модель:** `gemini-3.5-flash` (GA с 20.05.2026, дефолтная, нативный multimodal: аудио+видео+текст в одном запросе). Pro/Omni-Flash на момент записи ещё не общедоступны — Flash достаточно.
- **Пайплайн «смешные рилсы»:** видео → `ffmpeg` извлечь аудио → `gemini-3.5-flash` на полное аудио («найди смешное/интересное, таймкоды + почему» — слышит смех/подачу/паузу) → обсудить кандидатов с пользователем → `mlx-whisper large-v3` локально ТОЛЬКО на выбранные сегменты (точные слова + word-таймстемпы для реза) → нарезка. Whisper локальный = бэкбон таймкодов (бесплатно, любая длина); Gemini = поиск смешного по звуку.
- **Лимиты:** Gemini File API ~2GB / ~9.5ч аудио у Flash. Длинные репы — чанкать аудио. Whisper длину не парит.
