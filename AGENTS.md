# Cherry & Daddies — инструкции агенту

Это **полный рабочий репозиторий группы**, remote:
`git@github.com:alexomee/cherry-daddies-alex.git`. Здесь музыка, инструменты,
контент, вики и тексты. Сначала прочитай `CLAUDE.md` (музыкальные правила),
`wiki/index.md`; для lyrics — `docs/vocalist-workflow.md`.

## Репозиторный скилл Тани

На запрос `/tanya-texts`, «посмотри скилл tanya-texts», настройку рабочего места
Тани или работу с её экранными текстами прочитай
`.agents/skills/tanya-texts/SKILL.md` и действуй по нему. Это repo-scoped скилл
ChatGPT/Codex, он приезжает с клоном. На первом запуске объясни коротко весь
процесс, проверь инструменты/доступ к обоим репо и веди её по одному шагу.
Пользовательская инструкция от принятия приглашений до первой песни —
`docs/tanya-start.md`. Приглашение в риг basbit уже отправил (по сообщению Alex);
проверь его принятие и реальные права аккаунта tkozinets.

## Пользователь без опыта Git

Вокалистка Татьяна (`tkozinets`) работает через ChatGPT Desktop/Codex с доступом
к локальной папке и терминалу. Объясняй по-русски, коротко, через результат.
Сама выполняй технические шаги; не проси её вручную набивать TSV/команды Git.
Для авторизации в GitHub браузерный вход выполняет пользователь.

**Слова пользователя — точные действия:**

- «Добавь текст / подготовь песню» → получение текста, тайминги, сборка, превью.
- «Проверь» → автоматические проверки + просмотр/прослушивание; сообщи отдельно,
  что проверено программой, агентом и самой вокалисткой.
- «Сохрани» → проверка, commit, push в **основной** репо, проверка remote SHA.
- «Сохрани и отправь клавишнику» → то же + проверенная доставка выбранной песни,
  commit и push в **риг**. После доставки клавишнику ещё нужен Pull.
- «Всё верно» после конкретного превью → разрешение отметить его проверенным.
  Не выставляй `approve` только потому, что рендер/тесты прошли.

Если запрос «сохрани» касается другого контента, используй обычный Git, проверь
diff, добавь только относящиеся к задаче файлы и подтверди push. Команды lyrics
применяются именно к lyrics.

## Два репозитория

- Основной — текущая папка (название папки произвольное).
- Риг — `basbit/cherry-daddies-2000`, обычно соседняя папка
  `../cherry-daddies-2000`; другой путь: `CHERRY_RIG_REPO` или `--rig`.
- Перед началом проверь `git status` в обоих; запусти `lyric_workflow.py sync`.
  При конфликте/дивергенции объясни проблему и привлеки Alex; не делай reset,
  clean, force-push, произвольный stash или автоматический выбор «нашей» версии.

- Если push не удался: «Локально закоммичено, на GitHub ещё не отправлено».
  Сохрани commit, исправь причину, повтори команду; не создавай ложный успех.

## Получение текста

1. Найди песню и clip в `tools/lyric-launcher/songs.tsv`. Не угадывай номер
   по имени папки или порядку текущего концерта.
2. JamZone: проверь скачанную песню/`tiles.json` на этой машине; используй готовые
   слова и тайминги. `JAMZONE_JAMS` переопределяет папку загрузок.
3. Вне JamZone: используй `transcribe_lyrics.py` на вокальном стеме/записи.
   Для дуэта учти оба ведущих голоса, не теряй строки второго вокалиста.
   Сохраняй raw JSON и заметки о сомнительных участках. Повторы сохраняй как
   спеты в конкретной аранжировке. Не дописывай нераспознанное из головы.
4. Встроенный аудиоинструмент ChatGPT можно использовать, если он действительно
   доступен в текущем режиме; не заявляй, что «прослушала», если видишь только
   текст/метаданные. Если его нет — локальный Whisper. OpenAI API отдельно
   оплачивается; наличие подписки ChatGPT не означает наличие API-ключа.
5. `lyrics-timed/NN.tsv`: `m:ss.ss<TAB>строка`, в секундах **финального плейбека**.
   Отсчёт/offset добавляется один раз при транскрипции либо извлечении JamZone.
   Уже готовый playback-TSV получает offset=0. Исходная запись иной версии требует
   выравнивания с реальным ригом; совпадение длительности не доказывает синхрон.

## Обязательный lyrics-процесс

Команды и примеры находятся в `docs/vocalist-workflow.md`:

`sync → transcribe/extract → build → review → правки → build/review → approve → save [→ deliver --apply]`.

- Preview использует тот же ASS и MP4, что сцена, плюс музыкальный/вокальный guide
  и **реальные click/cues из рига**. Пользователь сверяет вступления/повторы.
- Для готового текста штатный путь: `sync → preview NN`. Чистые `all.wav` всех
  подготовленных песен доступны по `music/guide-catalog.json` в существующем R2;
  `guide NN` скачивает только выбранный файл. Публикация после рендера:
  `python3 tools/sync_site.py --guides-only`, затем commit/push каталога.
  Немой `clips/NN.mp4` не предлагать как review. Если guide отсутствует/устарел,
  назвать точный файл и команду публикации для Alex. Не отключать sparse checkout.
- `build` привязывает клип к исходникам и reference-аудио; `review` фиксирует
  хеши и состояние этой песни рига. Изменение после ревью требует нового ревью.
- Изменять исходный TSV/overrides, затем пересобирать. Правка только готового ASS
  не является воспроизводимым источником.
- Доставка — `lyric_workflow.py deliver NN --apply` или
  `deploy_clips.sh --index NN --apply`; без `--apply` только dry-run.
- Нормальный payload lyrics: выбранные `NN.ass`, `NN.mp4`, строка манифеста,
  provenance в `lyrics/deliveries/NN.json`.
- Для новой песни сначала согласуй свободный clip/PC и `bed_dir`, добавь строку
  в основной манифест. Требуется аудио плейбека в риге. После доставки сообщи
  «клип готов, подключение в MainStage требует проверки». Проводка делается
  по отдельному запросу по правилам `CLAUDE.md` на актуальном концерте.
