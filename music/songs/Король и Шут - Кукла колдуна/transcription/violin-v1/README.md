# Кукла колдуна — скрипки, MIDI-черновик v1

## Что открыть

**`kukla-violins-2voices.mid`** — основной файл: две отдельные монофонические дорожки Violin 1 / Violin 2 (456 и 296 нот). GM-инструмент Violin; в Logic назначить свой скрипичный патч.

- `kukla-violin-1.mid`, `kukla-violin-2.mid` — те же голоса по отдельности; при использовании общего файла их дополнительно импортировать не нужно.
- `violin-midi-guide.wav` / `.mp3` — MIDI, озвученный простым гармоническим синтезатором для проверки нот. Это технический тембр, не пример качества будущей скрипичной библиотеки.
- `compare-source-left-midi-right.wav` / `.mp3` — исходные strings **слева**, MIDI-гайд **справа**, уровни сопоставлены по активному RMS. Слушать в наушниках или поочерёдно каналы.
- `notes.csv` — все ноты, время в готовом плейбеке и исходном WAV, confidence и `review=True` для менее уверенных событий.
- `verification.json` — параметры и результат проверки MIDI.
- `check-*.png` — проверочные спектрограммы (их ось времени — исходный WAV, без render-смещения).

## Импорт в Logic

1. Проект **148.6 BPM, 4/4**, Smart Tempo — Keep. MIDI импортировать через **File → Import → MIDI File** с сохранением начала таймлайна.
2. Все файлы этой выдачи используют начало `auto-render`. В MIDI уже учтён сдвиг исходного WAV **+3.057926 с**. Ещё раз его добавлять не нужно.
3. Первая MIDI-нота находится около **0:03.248** (музыкальный вход по cue — 0:03.230). Не подтягивать первую ноту к самому началу проекта и не удалять начальную паузу.
4. Для аккомпанемента загрузить `auto-render/stems/`, выключить `other.mp3` и назначить двум MIDI-дорожкам инструменты. Аудиостемы не растягивать (Flex/Follow Tempo off).
5. Сначала слушать обе партии вместе; разделение голосов автоматическое, на переходах отдельные ноты могут требовать переноса между дорожками.

Тональность источника D minor, транспозиция 0. MIDI содержит номер ноты, а отображаемая Logic нумерация октав может отличаться от `notes.csv` (там MIDI 60 = C4); не компенсировать это транспозицией.

## Что проверено и что ещё править

Basic Pitch дал 2330 сырых событий. После анализа фундаментальных частот/гармоник, подавления октавных дублей, склейки вибрато-фрагментов и ограничения двумя голосами осталось **752 ноты**. Спектрально просмотрены вступление, участок 26–32.5 с, 60–66.5 с, тихая зона 160–173 с и финал 190–200 с исходника.

**Это редактируемая заготовка, не выверенная на слух партитура.** 152 ноты помечены `review=True`: это эвристика слабой уверенности/слабого фундаментального тона, а не измеренная частота ошибок. Источник содержит остатки других инструментов; особенно проверить тихие места и хвост, примерно **2:43–2:56 и 3:03–3:23 на таймлайне рендера**. Также возможны пропуски коротких нот, неточные окончания, лишние переатаки и неоднозначные октавы. Настоящее октавное удвоение иногда неотличимо от обертона; алгоритм предпочитает нижний поддержанный фундаментал. Масштабного приведения к гамме нет.

Проверка экспортов: обе дорожки монофонические, все длительности положительные, pitch-bend отсутствует, темп 148.6; независимое перечитывание MIDI (pretty_midi и mido), максимальная ошибка сериализации времени менее **0.46 мс**. Это точность сохранения тайминга, не точность определения музыкальных атак. Обратный синтез выполнен, полноценная слуховая приёмка в Logic остаётся за музыкантом.

## Воспроизвести

Python 3.11; зависимости `basic-pitch[onnx]==0.4.0`, `numpy<2`, `setuptools<81`, `matplotlib`, `soundfile`, `mido`.

```sh
python transcribe.py
```

Скрипт берёт WAV и mix/timeline из папки песни, кеширует ONNX-активации и CQT в `.cache/`, затем пересобирает MIDI/WAV/CSV/проверки. `--inspect` делает обзор исходника. MP3 и ZIP — упаковка через ffmpeg/zip. Сырой результат до чистки сохранён локально в `.cache/raw.mid` на исходном таймлайне (без +3.057926), полезен для восстановления спорных нот.
