# Синхронизация арпеджиатора клавишника с плейбеком

Статус: **черновик/обсуждение, вернуться позже.** Решение не выбрано.

## Задача

Клавишник играет арпеджиаторами. Неточные нажатия → ноты арпа уезжают с сетки и не стыкуются по звуку с плейбеком (click/cues/pb из StageTraxx). Хотим, чтобы арп шёл строго по темпу плейбека независимо от точности нажатия.

Сетап клавишника: **MIDI-клавиатура + ноут** (хост на ноуте — уточнить: Ableton / MainStage / Gig Performer / VST-хост).

## Принцип решения

Гнать арп от **тактового клока (MIDI Clock)**, а не от момента нажатия:
- арп: **clock sync ON**, note value выставлен (1/8, 1/16…), **free-run** (без рестарта по нажатию), аккорд в **latch** → шаги падают на сетку клока, неточное нажатие не возит рисунок.

## Откуда брать клок (3 варианта)

1. **MIDI Clock из StageTraxx → ноут.** ST шлёт Clock+Start, ноут (хост) = External MIDI sync. Связь: USB-MIDI / сетевой MIDI (RTP) / DIN через Rubix.
2. **E-RM Multiclock / Innerclock** — читает РЕАЛЬНЫЙ аудио-клик и делает из него MIDI Clock. Иммунен к рассинхрону bpm/оффсета. Железо, дороже.
3. **Ноут — клок-мастер** (Ableton/хост играет бэк + хостит синт): один общий клок на аудио и арп, ноль конвертеров. Самый чистый, но переносит воспроизведение с ST на ноут.

## ⚠️ Главный подвох (почему ST-клок не «бесплатный»)

ST **не слушает** аудио-клик. Он генерит MIDI Clock из **bpm песни + позиции воспроизведения** (от t=0 файла в темпе N). Совпадёт с нашим аудио-кликом ТОЛЬКО если аудио жёстко привязано к этой же сетке:
- **темп ровно постоянный и точный** (Logic 128.000 без автоматизации; в ST bpm = ровно столько). Иначе MIDI Clock и аудио расходятся за песню (дрейф).
- **фаза старта на сетке** — бounce должен начинаться на доле, а не «как попало».

## 🎯 Ключевое ограничение ДЛЯ НАШЕЙ группы

**Рисунок арпа у клавишника ПРИВЯЗАН к «раз» (даунбиту).** Значит оффсет старта бounce должен быть **целым числом ТАКТОВ**, а не просто долей.
- На 3 счёта смещать НЕЛЬЗЯ: ноты остались бы в тайминге, но цикл паттерна повернулся бы на 3 доли → «шаг 1» рисунка лёг бы на 4-ю долю такта вместо 1-й.
- Правильно: **бounce от тактовой черты** (без дробного оффсета; отсчёт/интро — целым числом тактов), постоянный точный темп, в ST bpm точный. Тогда и ноты, и фаза рисунка совпадают.

## Тест, в какой мы ситуации

Засинкать ноут по ST MIDI Clock, прогнать всю песню:
- арп держится с кликом все ~4 мин → аудио грид-локнуто, ST-клок годится;
- ползёт → bpm ≠ реальному темпу аудио → нужен E-RM или ноут-мастер;
- стабильный сдвиг/рисунок с «не той доли» → поправить точку бounce (на тактовую черту).

## Реализация правила «бounce от тактовой черты» (12.06.2026)

`tools/jamzone/logic_render_rebar.py "<песня>"` — пересобирает logic-render на сетку:
- меряет сетку по JZ Click-стему (lstsq по всем кликам; акцент ~200Hz = даунбит), сдвиг бounce↔стемы — кросс-корреляцией;
- t=0 = тактовая черта, **бар 0 = каунт-ин такт клика** (копия первого такта Click-стема), первый даунбит стема → бар 1, длина = целые такты;
- выход **WAV** (mp3 encoder delay ~26ms портил бы фазу против MIDI Clock), click из Click-стема, cues из `cue_track.wav`, pb-other/all — перевыровненные старые бounce;
- пишет `logic-render/timeline.json {offset_sec, bar_sec, bpm}`; `stagetraxx_render.py` читает его и сдвигает регионы (и берёт wav поверх mp3); старые mp3 → `logic-render/_old-<дата>/`.

Сделано для **Mr. Saxobeat** (bpm 127.0000, сетка ±0.3ms, 106 тактов). Для следующих песен: если Logic-бounce опять не от черты — просто прогнать rebar после бounce.
