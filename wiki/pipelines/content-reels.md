## Пайплайн «смешные рилсы из реп-видео»

Рабочая папка (вне git): `~/Downloads/rehearsal-reels/` (рендеры) + исходники `~/Downloads/IMG_*.MOV`.
Стейт в репо: скилл `.claude/skills/rehearsal-reels/SKILL.md`, скрипты `tools/reels/`, карта золота
`content/rehearsal-reels/NEXT-SESSION.md` + гочи `content/rehearsal-reels/project.md`. Старт сессии —
читать `NEXT-SESSION.md`.

Три звена (найти → отаймить → собрать):

1. **Gemini находит смешное по звуку.** Видео → `ffmpeg` извлекает аудио → `gemini-3.5-flash`
   (нативный multimodal, слышит смех/подачу/паузу) на полное аудио: «найди смешное/интересное,
   таймкоды + почему». Даёт кандидатов, обсудить с группой. **Гоча: таймкоды Gemini врут** (уплывали
   до ~157с) — на них не резать.
2. **mlx-whisper таймит локально.** `whisper large-v3` локально ТОЛЬКО на выбранные сегменты — точные
   слова + word-таймстемпы для реза (бесплатно, любая длина). Плюс «нейтральная проверка»:
   транскрибируй окно без подсказки → ловит галлюцинации Gemini.
3. **Нарезка.** Видео-субклипы (wide fit+blur / zoom-реакшн+эмодзи / cta) → concat; непрерывное аудио
   по битам (фейды только на стыках) → master; whoosh на джамп-катах; ASS-субтитры по говорящему
   (цвет) последними. Концовка — CTA-анонс концерта.

Ключ Gemini живёт в соседнем репо `agentiqa` (в вики НЕ дублируем — см. CLAUDE.md, секция «Gemini API»).
Лимиты Gemini File API ~2ГБ / ~9.5ч аудио — длинные репы чанкать; whisper длину не парит.

## Поза-синхрон под ноты (freeze / «живой фриз»)

Отдельный жанр: каждая нота (напр. синт-лид) триггерит позу группы. Прецедент — BOA-рилс
([../content/better-off-alone-reel.md](../content/better-off-alone-reel.md)).

- **Сетка нот — спектральный флакс, не амплитуда и не бит-грид.** Рифф переигрывает ноты на той же
  высоте с мягким ре-триггером (огибающая не падает) → амплитудное/питч-детектирование их СЛИВАЕТ.
  Метроном/бит-грид тоже мимо — рифф синкопирован против бита. Проверять сетку счётчик-видео (цифра
  инкрементится/вспыхивает на каждую ноту поверх микса).
- **Позы-холды — light-invariant motion (структурная корреляция, НЕ яркость).** Съёмка залита
  цветными LED-вошами (purple→green→orange строб) — покадровый diff по яркости читает КАЖДУЮ смену
  цвета как «движение» и рвёт один холд на клочки. Правильно: локальная структурная корреляция между
  кадрами `r = cov(f0,f1)/(std0·std1+eps)`, motion = взвеш. среднее `(1−r)`, вес `min(std0,std1)`
  (favors фактурное тело/края, игнорит плоское небо). Глобальная смена света оставляет структуру
  коррелированной (r≈1 → motion≈0); движущаяся конечность декоррелирует (спайк). По RGB, усреднить,
  гистерезис. **Всегда сверять глазами:** сэмплить кадры внутри холда — тела идентичны, меняется только
  цвет воша. Определение одной статичной позы (юзер): примерно равные положения тел, нет заметного
  движения рук/шагов; смена света позу НЕ завершает.
- **Full-band rule (жёстко):** все участники целиком в кадре, никого не режет край — edge-cut'ы юзер
  отвергает. Прогрессия поз должна быть смешной/нарастающей.

## Вкусы группы (что заходит)

Из `docs/content-history.md`, выучено 2026-06-11 на рил-подарке (см.
[../content/roma-seaboard-reel.md](../content/roma-seaboard-reel.md)):

- **Больше гэгов = лучше.** Плотность поп-апов/вставок группа выбрала над «чистым» минимализмом.
- **Билингва-цветные сабы работают** — RU жёлтый + EN белый; аудитория смешанная RU/EN (Лимассол),
  цветовое разделение читается. Дефолтный размер сабов крупноват для билингвы → FontSize=13, MarginV=45.
- **Сторителлинг-вставки ценятся** — удаление ключевых панчей обеднило историю.
- **Фидбек собирать со ВСЕЙ группы до итераций.** Правки по мнению одного участника ушли в сторону от
  консенсуса — денсер-версия по консенсусу победила «зачищенную» по одиночному фидбеку.
- Каждый произведённый кусок + выводы логировать в `docs/content-history.md`.

## R2-галерея референсов

Референс-видео (оригиналы клипов, что играем) — публичная галерея на `https://releases.agentiqa.com`,
префикс `cherry-daddies/videos/`. Правила заливки/шаринга через R2 — см.
[mainstage-rig.md](mainstage-rig.md) и CLAUDE.md «Шаринг рендера через R2» (креды/эндпоинт с ключами в
вики НЕ храним).

- **Key = YouTube id**: `cherry-daddies/videos/<id>.mp4` (URL-safe — пробелы/скобки ломают верификацию
  публичного URL). Исходники локально в `music/youtube/<title> [<id>].mp4`, генератор глобит по `[<id>].mp4`.
- **index сгруппирован по сетам + пронумерован** (СЕТ 1 / СЕТ 2 / НА БИС / ПРОЧЕЕ; номер карточки =
  позиция в сетлисте из `web/songs.json`). Текущая живая страница `cherry-daddies/videos/index-v2.html`.
- **HD-загрузка**: предпочитать h264 `avc1[height<=1080]`; если старый клип капит avc1 на 480/720 —
  брать vp9/av1 1080 и перекодировать в h264 (libx264 crf18). 403 при параллели — ретрай в одиночку
  (НЕ `player_client=android` — молча режет до 360p).
- **Edge-кэш гоча (Cloudflare):** перезапись ТОГО ЖЕ key → голый URL отдаёт СТАРЫЙ объект с edge-кэша,
  даже когда ориджин обновлён. **Фикс: каждую ревизию лить под НОВЫЙ key** (`index-v2.html`, `-v3`…) и
  раздавать этот URL. (Совпадает с правилом «версионировать каждый рендер».)
- `.html` требует явного `--content-type "text/html; charset=utf-8"` у аплоадера (иначе браузер качает
  файл, а не рендерит); `.mp4`/`.webm` тип выводятся по расширению — заметка в CLAUDE.md про
  octet-stream устарела.
