# Мультикам-видео концертов

Как из двух источников съёмки одного концерта собрать синхронное многокамерное видео: **широкая полнобэндовая камера** (общий план + источник звука) + **оператор** (крупные планы, ходит по сцене). Прецедент — гиг [2026-06-26](../gigs/2026-06-26-multicam.md).

> Рабочий каталог и исходники (`~/Downloads/…`, `~/Downloads/multicam/`) — временные, вне репо. Ниже — метод и записанные оффсеты; сами файлы могут не сохраниться.

## Источники

- **Широкие камеры** (общий план из глубины зала; ЭТО источник звука для всего видео): `~/Downloads/IMG_2689.MOV` — Сет 1, `~/Downloads/IMG_2690.MOV` — Сет 2. 1080p60.
- **Оператор** (вертикаль 4K60, герои-крупняки, ходит по гитаристу/вокалистке/банде): `~/Downloads/Видео/DIMAS*.MP4`. Сортировка по имени файла = хронология.

## Синхронизация (несущая логика, неочевидно)

Прямая аудио-кросскорреляция «широкая vs оператор» по ШИРОКОМУ окну **не работает**: танцевальные луповые песни автокоррелируют, разные микрофоны, кадры почти не пересекаются → ncc ≤ 0.18, разбросанные пики. Что работает:

1. **Часы оператор-камеры врут на +1h00m16.6s** (реальное = метка − 3616.6s). Калибровано по [Better Off Alone](../songs/better-off-alone.md): оператор `DIMAS0222-019` t0 = IMG_2689 287.36s. (Метки поначалу путают: оператор ~на час впереди → выглядело как «не тот файл».)
2. Для каждого клипа: `real_start = метка_создания_оператора − 3616.6s` → выбрать IMG-файл, покрывающий этот момент → грубый `prior` → **тесная** кросскор по onset-flux в окне `[prior ± 10s]` → пофреймовый OFF (ncc 0.5–0.68).
3. Контрольная сверка на общем LED-графике (картинка на видеостене), совпадающем в обоих кадрах.

## Рендер (EDL-driven)

`~/Downloads/multicam/_pipeline/`. Использовать **`gen_v2.py` + `render_edl_v2.py`** (v1 имел баг дрейфа).

**БАГ ДРЕЙФА (v1):** посегментный concat с `-t <dur>` при оператор 59.94fps vs IMG 60fps → каждый сегмент округляется коротко → видео уползает ВПЕРЁД от звука, накапливаясь (~0 → −1.3s к 40-й минуте), на краях компенсируется. На wide-only участках видно как рассинхрон губ/музыки на ОДНОЙ камере = чистый дрейф рендера, не ошибка синка.

**ФИКС:** каждый сегмент рендерить на ТОЧНОЕ число кадров (`-frames:v round(dur*60)`); таймлайн строить на кумулятивных квантованных длительностях (старт сегмента a0 = A_START + накопленное; wide `vss=a0`, оператор `vss=a0−OFF`); один сплошной IMG-звук → A-время видео == A-время звука по построению.

**ВЕРИФИКАЦИЯ (`m.py`):** на wide-only точках кросскор яркости выходного видео vs IMG_2689 (та же камера → ncc ~1.0), дрейф ~0 в нескольких таймкодах.

## Композиция

- Кроп оператора крупно: `0,500,2160,1215` (полная ширина, голова-до-пояса, безопасно по всем клипам).
- Цикл `[оператор-крупняк, wide]` 7.01s (4 такта при 135 bpm). «Нет оператора → вся камера целиком.»
- Выход горизонтальный 1080p60; вертикальный рилс — ре-рендер одним флагом (оператор снят вертикально).

Рендеры и EDL версионируются (никогда не перезаписывать — новый файл на ревизию) в `~/Downloads/multicam/<song>/`.
