# Подбор звука GM-800 под партию песни

Как найти на [GM-800](gm-800.md) звук под партию из стема (бас, лид) и проверить, что он встанет вровень с плейбеком, без игры руками и без прослушивания сотни тонов на слух. Синт сам играет партию по MIDI, звук пишется по USB, скрипт сравнивает его со стемом. Alex слушает только 2–3 финалиста в контексте песни.

Инструмент: `tools/gm800_match.py`. Список тонов: `gear/gm-800/tones.tsv` (официальный Sound List, разобран 2026-11-19: № / имя / MSB / LSB / PC / категория, 1208 строк; 21 = Synth Bass, 116 тонов).

## Процедура

```bash
gmm() { uv run -q --python 3.12 --with sounddevice --with numpy --with scipy --with python-rtmidi \
        --with librosa --with soundfile --with pyloudnorm tools/gm800_match.py "$@"; }   # zsh: не через $R
gmm line    "Попрошу" 28 44                      # 1. ноты партии из стема (bass.wav)
gmm sweep   "Попрошу" 28 44 --cat 21             # 2. все тоны категории, 3 такта каждый, рейтинг (~13 мин)
gmm scenes  "Попрошу" 28 44 7 14 27:80=127       # 3. сцены банды играют всю партию
gmm tones   "Попрошу" 28 44 645 667 --template 7 # 4. финалисты внутри сцены-шаблона (её октава/струны/FX)
gmm preview "Попрошу" 28 44 [--norm]             # 5. mp3 в контексте (--norm: все на уровне плейбека)
# после выбора Alex:
gmm build 31 7 645 "POPROSHU BASS"               # 6. сцена в INIT-слоте: шаблон 7 + тон 645 (бэкап до/после)
gmm anchor; gmm scenes "Попрошу" 28 44 31 7      # 7. уровень на пульте против pb (якорь и кандидат в одной сессии)
gmm level 31 part1 127                           # 8. PART LEVEL / SCENE LEVEL в памяти слота, повторить 7
```

- Такты `FROM TO` — как `mute`: с сильной доли `FROM` до сильной доли `TO`, `TO` не входит.
- Всё пишется в `analysis/gm800-match/<песня>/` (вне git): `line-*.json`, `scene-*.wav`, `tone-*.wav`, `report-*.json`, `sweep-*.json`, `preview/*.mp3`.
- `preview`: банда (все стемы, кроме `bass`) за 2 такта до партии и 4 после. Внутри партии — дубль синта на том уровне, который даст калибровка пульта; снаружи — стем. Плюс `00-original.mp3` для A/B.
- Перед первым прогоном (и после правки сцены 7) — `gmm anchor` → `analysis/gm800-match/anchor.json`. Прогон к прогону ±0.7 дБ: для точного ответа «вровень?» мерить якорь и кандидата в одной сессии.
- `tones` без `--template` играет тон на INIT-сцене (`--base 31`) на реальной высоте — так сравниваются сами тоны; с `--template N` — внутри сцены банды (партия 1 = тон, остальные выключены), это звук будущей сцены и её уровень.
- Только песни с постоянным темпом (`click: follow` / `tempo_zone` скрипт отклоняет). Нужен `abs_sec` у cue — то есть песня уже рендерилась.
- Если `--stem` не `bass`, партия берётся из другого стема (лид из `other`, `keys`).

- **`build`** собирает сцену во временном буфере (шаблон по PC, тон в партию 1, партии 2–4/R выкл.), читает все 88 блоков сцены и пишет их в слот, затем сверяет чтением. Слот должен быть INIT (`--force` для чужого). Дамп слота до/после — `gear/gm-800/backups/sysex/<дата>-slotNNN-{before,after}.json`. Чтение сцены — по 6 группам с приёмом через callback: опрос очереди терял первые ~17 блоков.
- **`level`** пишет PART LEVEL партии 1 (`02 00 06`) или SCENE LEVEL (`00 00 13`) прямо в память слота (DT1 в память сразу энергонезависима, см. [gm-800](gm-800.md)).
- Смену сцены в `mix.json` ставить с запасом ≥100 мс до первой ноты новой партии (сцена встаёт за 30–100 мс).

## Как устроено

- **Синт играет от USB.** `NOTE SOURCE = USB` по SysEx на время прогона, после — всегда обратно (`GK IN`) и сцена 1 MUTE (класс `Rig`, общий с `tools/live_levels.py`). Пока скрипт работает, датчик синт не запускает, и фраза звучит на выходах.
- **Сцены банды:** PC сцены, опционально CC (`27:80=127` — ASSIGN по CC80). Октаву сцены скрипт меряет пробной нотой A2. Ноты шлются как от датчика: на ту струну, что открыта у партии (сцены, разложенные по струнам, иначе звучат задвоенно — см. [level-anchors](level-anchors.md)). Ниже E2 гитара не берёт — партия поднимается на октаву.
- **ROM-тоны:** грузится INIT-сцена (`--base 31`, скрипт проверяет имя), тон партии 1 ставится во **временную** сцену: DT1 `10 02 00 00` = MSB, LSB, PC−1. В память прибора ничего не пишется, следующий PC стирает правку. Ноты идут на реальной высоте (у INIT нет сдвига октавы). Часть ROM-басов звучит на октаву ниже ноты (напр. 97 MG Saws Bass) — скрипт это видит и считает гармоники от реальной основной.
- **Тембр = гармоники + огибающая.** Профиль h1…h10 (дБ к основной) по медиане длинных нот, расстояние по h2…h9; огибающая ноты на 20/50/100/150/200/250 мс. Рейтинг = гармоники + 0.5 × огибающая. Moises-стем баса выше ~1 кГц пустой (верх уходит в другие стемы) — поэтому сравнение по гармоникам до h9, а не по спектру в полосах: полосы 1–6 кГц всегда показывали бы «синт ярче».
- **Уровень через басовый якорь.** Пульт калибруется так, что сцена 7 в «Солнышке» (такты 9–17, живой бас) равна слою `synth-bass` в PB Bass (17–25). `anchor` играет ту же партию на сцене 7 и пишет `G = LUFS(PB Bass 17–25) − LUFS(партия на сцене 7, USB)`. Дубль на пульте ≈ `LUFS(дубль, USB) + G`; сравнивается с группой `pb-bass` песни в тактах партии и после неё. LUFS у плейбека — моно-свёртка Stage Traxx (+3.01), у синта — стерео (у центрального баса одно и то же).
- Velocity 100 у всех нот. Живая игра по датчику даёт другую динамику, но одинаково в якоре и в песне — разница сокращается.

## Грабли

- BOSS TONE STUDIO держит порт — SysEx без ответа, скрипт останавливается. Закрыть BTS.
- Прерванный прогон (выпал кабель) оставляет `NOTE SOURCE = USB` — живая гитара не играет синт. Следующий запуск любого из двух скриптов чинит сам; руками: MENU > MIDI > NOTE SOURCE = GK IN.
- Перебор 116 тонов по 3 такта ≈ 12–13 мин; полный куплет на финалистов — по ~30 с.
