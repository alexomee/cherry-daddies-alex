# Tanya Texts — веди вокалистку от песни до сохранённого результата

Ты помогаешь Татьяне (`tkozinets`), которая не знакома с Git и терминалом.
Говори по-русски простыми словами. Выполняй технические действия сама, используя
готовые инструменты репозитория. За один раз проси от неё только одно необходимое
действие: войти в аккаунт, выбрать песню, дать аудио или посмотреть видео.

## Сначала восстанови контекст

Найди корень **основного полного репозитория** по расположению этого скилла:
он находится в `.agents/skills/tanya-texts/`. Имя локальной папки может отличаться.
Прочитай:

1. [AGENTS.md](../../../AGENTS.md) — правила общения, сохранения и работы с двумя репо.
2. [Памятку настройки](../../../docs/tanya-start.md) — если это первый запуск.
3. [Технический workflow](../../../docs/vocalist-workflow.md) — команды и данные.
4. [CLAUDE.md](../../../CLAUDE.md), раздел про сценические тексты; для конкретной
   песни — [wiki/index.md](../../../wiki/index.md) и страницу песни.

Поддерживаемые репозитории:

| Назначение | GitHub | Обычное расположение |
|---|---|---|
| Весь рабочий проект группы: музыка, инструменты, тексты, контент и вики | `alexomee/cherry-daddies-alex` | `~/Music/CherryDaddies/cherry-daddies-alex` |
| Сценический риг клавишника | `basbit/cherry-daddies-2000` | соседний `cherry-daddies-2000` |

Другой путь рига передавай через `CHERRY_RIG_REPO` или глобальный аргумент `--rig`
у `lyric_workflow.py` **перед** подкомандой. Не подставляй пути с компьютера Alex.

## Первый запуск: «посмотри скилл и объясни, что делать»

Сначала дай короткую карту процесса, например:

> Я помогу тебе подготовить текст для экрана. Ты выбираешь песню; я получаю
> слова и расставляю время показа; ты смотришь видео и говоришь, что поправить.
> После твоего подтверждения я сохраняю результат на GitHub. По просьбе также
> отправляю его клавишнику. Сначала проверю настройку компьютера.

Затем **проверь фактическую готовность**, а не объявляй, что всё установлено:

- Исходи из чистого Mac: Git, Homebrew, gh и Python-окружение могут отсутствовать.
  До первой Git-команды проверь инструменты. Для отсутствующего Git проверь
  `xcode-select -p`, при необходимости запусти `xcode-select --install`, попроси
  Таню нажать «Установить» в системном окне и дождись завершения; затем проверь
  `git --version`. Полный Xcode для этого не нужен. Если Homebrew отсутствует,
  помоги установить его по `https://brew.sh`; затем установи недостающий `gh`.
  Клонирование начинай только после готовности Git и авторизации. Системные
  подтверждения делает пользователь, терминальные команды выполняешь ты.
- Найди оба клона и проверь `git remote -v`, текущую ветку и `git status`.
- Если клона нет, используй HTTPS-адреса из памятки; существующую папку сначала
  осмотри. Повторный запуск настройки должен использовать уже существующий клон.
- Проверь `gh auth status`, затем `gh api user --jq .login`. Для настройки Тани
  ожидается `tkozinets`; если вошёл другой человек, уточни, не переключай его молча.
- Проверь права `gh api repos/OWNER/REPO --jq '.permissions.push'` для обоих репо.
  Приглашения уже отправлены по сообщению Alex, но приглашение ещё нужно **принять**.
  Если приватный риг недоступен, помоги принять приглашение, проверь аккаунт.
  Public/read-доступ к основному репо не подтверждает возможность сохранить изменения.
- Для входа открывай обычную авторизацию GitHub через
  `gh auth login --hostname github.com --git-protocol https --web`, затем
  `gh auth setup-git`. В браузере пользователь входит сама; не проси присылать
  токен или пароль в чат.
- Проверь Git `user.name`/`user.email` в каждом клоне. Недостающий email спроси;
  можно взять noreply из GitHub → Settings → Emails. Настраивай локально для
  этих репозиториев, не копируй автора коммитов Alex.
- Определи ОС и архитектуру сама. Установщик рассчитан на Mac: проверь Homebrew,
  при необходимости помоги установить его с `https://brew.sh`, затем запусти
  `bash tools/lyric-launcher/setup.command` из основного репо.
- Используй `tools/lyric-launcher/.venv/bin/python` для workflow. Запусти `doctor`.
  Он проверяет инструменты и read-доступ; write-доступ проверен отдельно выше.
- Проверь JamZone и напомни скачать выбранную песню внутри приложения. Наличие
  каталога JamZone ещё не означает, что конкретный `tiles.json` скачан.

После проверки сообщи коротко: что готово, какой **один** шаг нужен от неё сейчас.
Если всё готово, спроси: **«Какую песню подготовим первой?»** Не начинай другую
песню и не отправляй существующие клипы просто ради проверки установки.

## Каждый рабочий сеанс

Сначала проверь состояние обоих репозиториев. Получи свежие версии через `sync`:

```bash
PY=tools/lyric-launcher/.venv/bin/python
FLOW=tools/lyric-launcher/lyric_workflow.py
"$PY" "$FLOW" sync
```

Команды выполняй из корня основного репо. При конфликте, чужом staging или
дивергенции объясни конкретную проблему; сохрани текущее состояние и привлеки
Alex при необходимости. Не делай force-push/reset/clean или произвольный stash.

Найди выбранную песню в `tools/lyric-launcher/songs.tsv` и странице вики. `NN` ниже
означает её **реальный clip-ID**, а не номер из примера или номер папки.

### 1. Получи текст без набора с нуля

**JamZone:** используй скачанные `tiles.json`, `cat` из манифеста и готовые
тайминги. Для генерации нужны reference-аудио в таймлайне плейбека и offset из
`auto-render/timeline.json` или отдельно подтверждённое смещение.

**Русская / другая песня вне JamZone:** найди переданный вокальный стем или запись.
Для дуэта учти оба ведущих голоса. Запусти локальную транскрипцию:

```bash
"$PY" tools/lyric-launcher/transcribe_lyrics.py '/путь/к/vocals.wav' \
  --language ru --offset OFFSET --out tools/lyric-launcher/lyrics-timed/NN.tsv
```

Замени `NN` и `OFFSET` реальными значениями. Для аудио, уже совпадающего с
финальным плейбеком от нулевой секунды, явно укажи `--offset 0`. Для исходного
стема учитывай сценический отсчёт ровно один раз. Перестановки секций, другой
темп и обрезки требуют выравнивания; одним смещением их не исправить.

Сохраняй `.raw.json` и `.review.txt`. Сомнительные слова проверяй короткими
фрагментами аудио, повторы — по конкретной записи. Не угадывай потерянные строки.
Если готовый текст есть, можно использовать существующие `align_lyrics.py` /
`auto_align.py`; команды и зависимости описаны в техническом workflow.

Если встроенная транскрипция ChatGPT реально доступна в этом сеансе, её результат
тоже можно использовать. Наличие подписки не означает доступ к Audio API из
Python и не даёт права выдумывать результат прослушивания. Воспроизводимый
вариант по умолчанию — локальный Whisper из установленного окружения.

**Отсутствующие медиа:** Git не скачивает исключённые аудиофайлы. Попроси конкретно
нужный файл у Тани/Alex, а не предлагай ей печатать всю песню. Для preview нужен
музыкальный/вокальный guide на сценическом таймлайне, обычно `auto-render/all.wav`.
Клик и cue добавятся из рига, поэтому guide должен быть без уже подмешанных cue.

### 2. Собери и покажи настоящее превью

```bash
"$PY" "$FLOW" build NN --audio '/путь/к/playback-frame-guide.wav'
"$PY" "$FLOW" review NN
```

`build` использует `lyrics-timed/NN.tsv`, если он есть; иначе JamZone либо
статический `lyrics-manual/NN.txt`. TSV содержит playback-время, offset уже учтён.
`review` создаёт `.local/NN-review.mp4` с тем же сценическим ASS и MP4,
таймкодом и реальными click/cues рига. На Mac открой видео через `open`, чтобы
Таня могла его посмотреть, и назови песню/версию.

Попроси проверить всю песню: слова, повторы, удобство чтения, входы и конец.
Пусть отвечает обычной фразой: «на 1:24 вместо … должно быть …».
Исправляй исходный TSV/TXT или JamZone `overrides/NN.tsv`, затем снова build/review.
Не правь только готовый ASS: следующая сборка потеряет такую правку.

### 3. Отметь подтверждение и проверь

Только когда Таня явно подтвердила **показанное** превью:

```bash
"$PY" "$FLOW" approve NN --reviewer Татьяна
"$PY" "$FLOW" check NN
```

Успешные автоматические тесты или генерация видео не заменяют её подтверждение.
Хеши связывают review с исходниками, клипами и аудио рига. Если после ревью
что-то изменилось, пересобери и покажи новую версию; не обходи проверку.

### 4. Выполни именно запрошенное сохранение

**«Сохрани»:**

```bash
"$PY" "$FLOW" save NN --message 'lyrics: краткое описание изменения'
```

**«Сохрани и отправь клавишнику»:** сначала тот же `save`, затем:

```bash
"$PY" "$FLOW" deliver NN
"$PY" "$FLOW" deliver NN --apply
```

Доставка меняет только выбранную пару `.ass`/`.mp4`, строку манифеста и provenance
в риге, сохраняет чужие песни и ссылается на исходный commit. Новая версия
плейбека этой песни требует повторной проверки синхрона.

При отказе push скажи: **«Локально сохранено, на GitHub ещё не отправлено»**,
назови причину и следующий шаг. Commit сохраняется для повторной отправки.
Не отвечай «готово» только по успешному commit.

## Совершенно новая песня

Сначала сверь оба манифеста, свободный clip-ID / PC и существующий `bed_dir` рига.
`pc_field = clip + 1`; существующие ID не перенумеровывай. Для новой песни нужен
подготовленный сценический плейбек. Если его нет, договорись с Alex о подготовке.

Добавь только нужную строку в основной `songs.tsv`, подготовь текст и пройди
тот же процесс. После доставки сообщи **«клип готов; подключение в MainStage
нужно проверить»**. Наличие строки манифеста не доказывает настройку MIDI в
актуальном концерте. Подключение — отдельная задача клавишника/Alex.

## Ответ по завершении

Не перегружай Таню техническим отчётом. Дай понятные статусы и ссылки:

> **«Название»**: текст проверен и сохранён на GitHub — [изменения].
> Клавишнику отправлено — [изменения в риге]. Ему осталось сделать Pull.

Вторую строку выводи только при выполненной доставке. «На ноутбуке клавишника
обновлено» можно сказать только после подтверждения самого клавишника.
